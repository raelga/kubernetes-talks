### Azure: interactive identity and Blob locking

```bash
az login
read -r -p 'Instructor subscription UUID: ' AZ_SUBSCRIPTION
read -r -p 'Authorized Azure region: ' AZ_LOCATION
read -r -p 'Authorized small SKU (Standard_B1s, Standard_B1ms or Standard_B2s): ' AZ_VM_SIZE
read -r -p 'Path to existing PUBLIC SSH key (.pub, never private): ' AZ_PUBLIC_KEY
export AZ_SUBSCRIPTION AZ_LOCATION
export TF_VAR_subscription_id="$AZ_SUBSCRIPTION" TF_VAR_location="$AZ_LOCATION"
export TF_VAR_vm_size="$AZ_VM_SIZE" TF_VAR_ssh_public_key_path="$AZ_PUBLIC_KEY"
az account show --subscription "$AZ_SUBSCRIPTION" --output json

read -r -p 'EXISTING backend resource group (same subscription): ' AZ_STATE_RG
read -r -p 'EXISTING backend storage account: ' AZ_STATE_ACCOUNT
read -r -p 'EXISTING private backend container: ' AZ_STATE_CONTAINER
az storage account show --subscription "$AZ_SUBSCRIPTION" --resource-group "$AZ_STATE_RG" \
  --name "$AZ_STATE_ACCOUNT" --output json
az storage container show --account-name "$AZ_STATE_ACCOUNT" --name "$AZ_STATE_CONTAINER" \
  --auth-mode login --output json
terraform -chdir="$LAB_ROOT/azure/terraform" init \
  -backend-config="subscription_id=$AZ_SUBSCRIPTION" \
  -backend-config="resource_group_name=$AZ_STATE_RG" \
  -backend-config="storage_account_name=$AZ_STATE_ACCOUNT" \
  -backend-config="container_name=$AZ_STATE_CONTAINER" \
  -backend-config="key=upc-2026/cloud-03/$LAB_ID/azure.tfstate" \
  -backend-config="use_azuread_auth=true"
terraform -chdir="$LAB_ROOT/azure/terraform" workspace show
```

The active CLI account must belong to the subscription tenant; `az account show` checks this without relying on the default subscription. The backend uses CLI/Entra login, not an access key. Blob provides locking through a state-object **lease**. `init` must succeed and `workspace show` must report `default`; separation comes from the unique key, not multiple workspaces for the same lab_id. If unexpected prior state exists, **stop and investigate ownership**, rather than automatically importing or deleting. Do not use `-migrate-state`, `-reconfigure`, `force-unlock` or delete leases to ignore a discrepancy. A public key in configuration/state is not a secret; the private key must never enter Terraform. SSH is not opened or needed to view HTTP.

Do not leave a failed demonstration consuming resources indefinitely.

The Blob endpoint requires authentication and serves no anonymous content: private container, `allow_nested_items_to_be_public=false`, shared keys disabled. ## Safe destruction and read-only verification

Preserve outputs before destroy to identify storage. **Never run `az group delete`, delete the project/backend bucket, reset Academy or clean shared resources.** Use only `terraform destroy` for the exact root, backend, lab_id and workspace. Review the destruction plan before confirming; do not use `-auto-approve`. Azure can delete data when deleting the account: this root has no protective `force_destroy`; therefore keep it empty and inspect it first. If unexpected content appears, **stop**, confirm ownership and preserve it; do not automatically empty it to make destroy succeed.

```bash
AZ_STORAGE="$(python3 -c 'import json,sys; print(json.load(open(sys.argv[1]))["storage_account"]["value"])' "$EVIDENCE_DIR/azure-outputs.json")"
# Must succeed and show []: includes deleted blobs, snapshots and versions.
az storage blob list --account-name "$AZ_STORAGE" --container-name private \
  --auth-mode login --include d s v --output json
terraform -chdir="$LAB_ROOT/azure/terraform" workspace show
terraform -chdir="$LAB_ROOT/azure/terraform" state list
terraform -chdir="$LAB_ROOT/azure/terraform" plan -destroy -lock-timeout=60s
terraform -chdir="$LAB_ROOT/azure/terraform" destroy -lock-timeout=60s
terraform -chdir="$LAB_ROOT/azure/terraform" state list
python3 "$LAB_ROOT/scripts/cleanup.py" live --provider azure --lab-id "$LAB_ID" \
  --subscription "$AZ_SUBSCRIPTION"

GCP_BUCKET="$(python3 -c 'import json,sys; print(json.load(open(sys.argv[1]))["bucket_name"]["value"])' "$EVIDENCE_DIR/gcp-outputs.json")"
gcloud storage buckets describe "gs://$GCP_BUCKET" --project "$GCP_PROJECT" --format=json
# Inspect objects/versions in the console or with ls; an error does not imply emptiness.
gcloud storage ls --all-versions "gs://$GCP_BUCKET/**" --project "$GCP_PROJECT"
terraform -chdir="$LAB_ROOT/gcp/terraform" workspace show
terraform -chdir="$LAB_ROOT/gcp/terraform" state list
terraform -chdir="$LAB_ROOT/gcp/terraform" plan -destroy -lock-timeout=60s
terraform -chdir="$LAB_ROOT/gcp/terraform" destroy -lock-timeout=60s
terraform -chdir="$LAB_ROOT/gcp/terraform" state list
python3 "$LAB_ROOT/scripts/cleanup.py" live --provider gcp --lab-id "$LAB_ID" \
  --project "$GCP_PROJECT" --bucket "$GCP_BUCKET"
```

In GCP, `ls` without matches may return a “no matched objects” error: distinguish it from permission/API errors and confirm bucket accessibility with `describe`; `force_destroy=false` prevents automatic deletion of nonempty content. Do not change it to `true` to resolve a failure. If the provider retains data through soft delete/retention, review policy/costs and retention duration even after the active resource disappears; an empty inventory does not certify a closed bill.

`cleanup.py` is read-only. Azure checks absence of the **dedicated group** and, if present, enumerates all its resources, not just tagged VMs. GCP queries VMs, disks, addresses, VPC, subnets and firewalls by exact lab name/prefix and the exact bucket; it does not audit every organizational resource or services never created by this root. An API failure causes nonzero exit and **VERIFICATION INCOMPLETE**, not “zero resources”. Remaining resources cause nonzero exit and require investigation against the exact state, not blind deletion. Query again after eventual consistency without hiding failures.

Destroy does not remove the backend, previous state versions or local credentials. Retain authorized cleanup evidence outside the repository; treat plans/captures/outputs as private and remove them after class according to institutional policy. Do not commit credentials, keys, `.terraform`, state/plans/backend configuration or real captures.
